Usability Test of The Economist

The Economist

What is a Usability Test?

Usability testing is a method used to learn how easy or difficult it is for people to use a service by observing them completing “real life” tasks within the service. The goal is to identify your users’ pain points and create solutions that are user-focused to produce a service that is easy to use.

What Are We Testing?

This page is the summary and breakdown of the usability test conducted on The Economist to see how easy it is for a user to properly navigate givens a set of 5 tasks. The primary goal here was to identify any pain points on this given website when being used to complete normal tasks in regard to the website.

Task 1: Log In/Sign Up

Time: 47.63s

The user was faced with the task of creating an account and signing up for the newsletter. Initially, the user had some struggles, as he clicked the big subscribe button at the bottom of the page. yet, after some time, eventually made his way to the correct user sign up section.

Task 2: Find Recent Article Regarding Home State

Time: 2m 12.72s

Here the user was tasked with the goal of finding a recent article regarding his home state (California). Initially, the user found his way to the California article section via the search tab, yet was initially did not sort by date, only relevance,

Task 3: Find Information About AI in an Asian Country

Time: 18.04s

The user was tasked with finding an article regarding AI in any given asian country. The user found this fairly quickly, as he clicked the china tab at the top of the page and one of the top article by default was regarding AI. There was no usability struggle in this task for the user.

Task 4: Start Weekly Crossword Puzzle

Time: 40.65s

Here the user was tasked with finding the daily crossword puzzle. Initially, he scrolled to the bottom of the page first, then found his way back to the top main bar and found the games sections. from there, he found the crossoword very quickly.

Task 5: Listen to a Podcast That is Named an Onomatopoeia

Time:24.46s

Finally, the user tasked with finding a podcast that is named after an onomatopoeia. Due to his lack of expansive vocabulary, the user initially did not know what an onomatopoeia was (It’s ok that I say this, I was the user). After that was cleared, he quickly found the podcasts by hitting the search bar, and the podcast title Boom was there shortly after.
